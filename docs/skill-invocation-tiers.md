# 스킬 호출 계층 (Invocation Tiers)

스킬이 **언제 발동할지 예측 가능하게** 만들기 위한 규약이다.

## 문제

스킬이 늘어나면 "이게 왜 지금 켜졌지?"가 생긴다. 오케스트레이터 성격의 스킬(사용자와 긴 대화를 끌고 가거나, 서브에이전트를 대량으로 띄우거나, 외부에 영향을 주는 스킬)이 모델 판단으로 임의 발동하면 다음이 깨진다.

- 사용자가 요청하지도 않은 심문/패널/부하테스트가 시작된다
- 오케스트레이터가 오케스트레이터를 부르면서 호출 깊이가 예측 불가능해진다
- 토큰이 사용자 동의 없이 크게 소모된다

## 두 계층

| 계층 | 의미 | 발동 조건 |
|------|------|-----------|
| **user-invoked** | 오케스트레이터. 프로세스를 끌고 가고, 사용자 시간·토큰·외부 부작용을 요구한다 | 사용자가 `/커맨드`를 직접 입력했거나 자연어로 **명시 요청**했을 때만 |
| **model-invoked** | 재사용 규율. 작업 성격에 맞으면 모델이 알아서 적용한다 | 모델이 판단해서 자유롭게 |

## 호출 규칙

```
user-invoked  ──▶ model-invoked   ✅ 허용
model-invoked ──▶ model-invoked   ✅ 허용 (순환 금지)
user-invoked  ──▶ user-invoked    ❌ 금지  (오케스트레이터 중첩 금지)
model-invoked ──▶ user-invoked    ❌ 금지
```

**참조는 호출이 아니다.** 다른 스킬의 `references/*.md`를 데이터로 읽거나, 문서에서 "이럴 땐 `/agent-teams`를 쓰세요"라고 안내하는 것은 호출이 아니므로 규칙 대상이 아니다. 금지되는 것은 실행 위임뿐이다.

경계가 흐려지기 쉬우므로 동사로 구분한다.

| 표현 | 판정 |
|------|------|
| 읽는다 / 참조한다 / 안내한다 / 제안한다 | ✅ 참조 |
| **절차 참조** — 다른 파일에 적힌 단계를 읽고 **내가** 수행한다 | ✅ 참조 |
| 실행한다 / 자동 실행 / 전환한다 / 인계한다 / 연동된다 | ❌ 호출 |

**절차 참조가 중복의 정답이다.** user-invoked 둘이 같은 절차를 필요로 할 때, 절차를 복제하지 말고 원본 파일을 지정해 "그 파일을 읽고 그대로 수행하라"고 쓴다. 복제는 규약을 지키는 것처럼 보이지만 원본이 바뀔 때 조용히 갈라진다.

실제 사례 — `/dev-cycle`은 `/jira:start`를 실행하지 않고, `~/.claude/commands/jira/start.md`의 단계 0~2를 읽어 스스로 수행한다. 과거 이 절차를 3줄로 복제해뒀을 때 브랜치명 MANDATORY 규칙과 `main/develop pull`이 누락돼, 같은 저장소에서 진입 경로에 따라 브랜치 네이밍이 갈리는 상태였다.

**Agent 도구 직접 호출은 우회로다.** user-invoked 스킬이 다른 user-invoked 스킬의 기능이 필요하면, 그 스킬을 부르지 말고 필요한 에이전트를 Agent 도구로 직접 호출한다. (`/mvp`가 `expert-panel` 스킬 대신 `@expert-*` 에이전트를 직접 병렬 호출하는 방식)

## 표기 방법

### 스킬 (`skills/*/SKILL.md`)

프론트매터의 `metadata` 아래에 선언한다. 최상위 키를 새로 만들지 않는 이유는 `skills/skill-creator/scripts/quick_validate.py`가 최상위 키를 `name / description / license / allowed-tools / metadata`로 제한하기 때문이다.

```yaml
---
name: grill-me
description: ...
metadata:
  invocation: user-invoked
---

> **호출 계층: user-invoked** — 사용자가 직접 호출했거나 명시적으로 요청했을 때만 실행한다. 다른 user-invoked 스킬/커맨드를 호출하지 않는다.
```

본문 맨 위의 인용 블록은 모델이 스킬을 로드하는 순간 반드시 읽는 위치이므로, 훅이 동작하지 않는 환경에서도 규약이 전달되는 최종 방어선이다.

### 커맨드 (`commands/*.md`)

커맨드는 **정의상 전부 user-invoked**다. 사용자가 타이핑해야 실행되는 것이 슬래시 커맨드의 존재 이유이므로 별도 표기를 하지 않는다.

예외적으로 모델이 자유롭게 불러도 되는 커맨드는 프론트매터에 명시적으로 opt-out 한다.

```yaml
metadata:
  invocation: model-invoked
```

## 강제 수단

### 1. 본문 규약 (항상 동작)

스킬이 로드되면 본문 최상단 인용 블록이 함께 읽힌다. 훅 유무와 무관하게 작동하는 기본 방어선.

### 2. PreToolUse 훅 경고 (`hooks/guardrail-skill.py`)

사용자가 `/커맨드`를 직접 입력하면 스킬이 곧바로 로드되어 **Skill 툴을 거치지 않는다.** 반대로 모델이 스스로 꺼낼 때는 반드시 Skill 툴을 호출한다. 따라서 이 훅이 발동했다는 것은 곧 **모델이 자체 판단으로 발동시켰다**는 뜻이며, 이를 신호로 경고를 띄운다.

차단(exit 2)하지 않고 경고(exit 0)만 하는 이유는, 사용자가 자연어로 "그릴 좀 해줘"라고 명시 요청한 경우도 Skill 툴을 타기 때문이다. 이 경우까지 막으면 오탐이 된다. 판단은 모델에게 남기고 근거만 제공한다.

### 3. (선택) 하드 차단

특정 커맨드를 모델이 절대 못 부르게 하려면 커맨드 프론트매터에 Claude Code 네이티브 필드를 쓴다. 경고보다 강하지만, 자연어 요청까지 막히므로 사용자가 매번 슬래시 커맨드를 타이핑해야 한다.

```yaml
disable-model-invocation: true
```

## 현재 분류

### user-invoked

| 대상 | 근거 |
|------|------|
| `grill-me` | 사용자에게 수십 개 질문을 던지는 대화형 심문 |
| `grill-with-docs` | 동일 + 문서 갱신까지 동반 |
| `expert-panel` | 전문가 에이전트 병렬 대량 실행 (토큰 큼) |
| `project-scaffolding` | 프로젝트 구조를 대규모로 생성/변경 |
| `continuous-learning` | 지식 베이스에 영구 기록을 남김 |
| `load-testing` | 실제 대상에 트래픽을 발생시키는 외부 부작용 |
| `youtube-collector` | 외부 API 호출 + 할당량 소모 |
| `skill-creator` | 저작 도구. harness 자체를 변경 |
| `slash-command-creator` | 저작 도구. harness 자체를 변경 |
| `hook-creator` | 저작 도구. 설정/훅을 변경 |
| `commands/**` 전체 | 슬래시 커맨드는 정의상 사용자 호출 |

### model-invoked

| 대상 | 근거 |
|------|------|
| `tdd-workflow` | 구현할 때 항상 적용되어야 할 규율 |
| `quality-gate` | 검증 단계에서 오케스트레이터가 끌어다 쓰는 체크리스트 |

## 새 스킬을 만들 때

아래 중 **하나라도** 해당하면 user-invoked다.

- [ ] 사용자에게 여러 차례 질문하며 대화를 끌고 가는가
- [ ] 서브에이전트를 여러 개 띄우는가
- [ ] 외부(네트워크·API·배포 대상)에 영향을 주는가
- [ ] 파일·설정·지식베이스에 영구 기록을 남기는가
- [ ] 토큰을 크게 소모하는가

모두 아니고 "특정 작업을 할 때 지켜야 할 규율/패턴"에 가깝다면 model-invoked다.
